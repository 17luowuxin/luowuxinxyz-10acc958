# 新项目登录与卡密注册：填写清单

## 当前状态

这是一份接入准备说明，尚未切换当前应用，也没有在新项目创建账号、卡密或部署注册服务。新项目的真实地址和公开密钥还未提供。

目标：新外部项目保存账号和卡密；角色、聊天、记忆、朋友圈、游戏等个人内容保存在手机。保留登录，不改成免登录或本机卡密验证。

本项目已经接入 Lovable Cloud，不能从项目中解除它。新方案是在应用里单独接入用户自己的外部项目，不是将现有 Cloud 换绑成新项目。更换登录也不等于所有功能都已脱离 Cloud。

## 你需要填写哪些信息

| 信息 | 怎么辨认 | 填写方式 |
| --- | --- | --- |
| 新项目地址 | 标签为 `Project URL`，应为新项目提供的 HTTPS 地址 | 可以发给我；不要填项目名称、管理页面地址或 AI 接口地址 |
| 新项目公开密钥 | 标签为 `Publishable key` 或旧格式 `anon public key` | 可以发给我；必须和上面的地址属于同一个项目 |
| 应用网址 | 用户实际打开小手机的网址 | 暂用 `https://bbiphone.lovable.app`；若改用自己的域名，告诉我最终网址 |

填写示例在同目录的 `external-auth-connection.example.json`。其中空字符串表示尚未配置，不是可用配置。它只是清单，当前应用不会自动读取这份文件。

**不要发到聊天里的信息：**数据库密码、`service_role`、`Secret key`、`sb_secret_` 开头的密钥、用户密码。这些不属于公开连接配置。

前期准备只需项目地址和公开密钥。若后续需要部署或管理卡密的后台凭证，会通过安全填写框收取，不放入网页或此说明。刚更换的 `LOVABLE_API_KEY` 不是新项目公开密钥，不能填在这里。

## 账号注册与卡密流程

1. 管理员在新项目生成卡密，普通用户不能查看卡密库存或修改使用状态。
2. 用户在小手机填写邮箱、密码、卡密；登录时只填写邮箱和密码。
3. 网页只向新项目发起注册，不绕到暂停的 Cloud，也不先在手机判定卡密有效。
4. 新项目在创建账号的同一事务内校验并消费卡密：无效、已使用或并发抢占失败的卡密不能创建账号；账号创建失败时，事务回滚，卡密不被误扣。
5. 默认保留邮箱确认，用户完成邮箱确认后登录；不擅自改成注册后自动登录。邮箱未确认的账号也已成功占用卡密，需要允许重发确认邮件，而不是重复注册。
6. 登录后用账号编号区分本机数据，退出登录不清除角色和聊天。切换账号不能混用另一账号的本机记录。

本方案初期不需要用户提供管理员密钥给网页。可以使用新项目自己的注册入口配合服务器上的原子卡密校验；管理员卡密维护只能在受保护的服务端执行。

## 接入需要完成的工作

### 新项目侧

- 开启邮箱密码注册及登录，设置应用网址和对应的邮件跳转地址。
- 为确认邮件配置可靠的发送方式，核实真实用户能够收到邮件及发送限额。
- 创建卡密表，启用访问保护；不给匿名用户及普通用户库存读取或写入权限。
- 安装账号创建时的原子卡密校验，限制每张卡密只能成功注册一个账号；并检查公开注册入口也无法绕过卡密。
- 若保留应用管理员功能，管理员角色单独保存、服务端验证，不能通过用户自己填写的资料或本机标记授予。
- 旧账号与旧卡密不会自动进入新项目；旧项目恢复后才能进一步核实可迁移内容。

### 应用侧

- 替换外部项目的公开连接配置及自定义域名的代理目标，登录和注册仅走新项目。
- 去掉先试 Cloud 的登录等待与注册对 Cloud 函数的依赖；旧账号如何回迁另行处理，不自动覆盖本机数据。
- 将新账号的个人内容默认保存在本机，检查所有页面仍在读取远端数据的地方。
- 私聊、群聊、朋友圈、游戏、记忆总结、TA 的手机等现有 AI 功能逐个检查；只改登录不会让它们自动脱离 Cloud。
- 用户自己的 AI 接口必须实际测试成功才能使用。若接口禁止浏览器直接连接，需要兼容的接口或单独的服务端转发，不能用公开网页泄漏管理员密钥。
- 保留本机导出与导入备份。新项目账号编号不同于旧账号，迁移前必须确认原数据归属。

### 验证清单

- 有效卡密注册成功，邮箱确认后能够登录。
- 无卡密、无效卡密及已使用卡密均不能注册。
- 同一卡密同时注册两个账号时，只有一个成功。
- 账号创建失败不会消耗卡密。
- 普通用户无法读取卡密库存、修改使用状态或授予自己管理员身份。
- Cloud 不可用时，新项目注册和登录仍正常工作。
- 本机新增角色并聊天，刷新、退出再登录后内容仍在；另一账号看不到这些记录。
- 正常的 Wi-Fi 和手机流量下分别测试登录，明确提示真实失败原因。

## 不要直接照搬旧数据库初始化文件

仓库旧的完整外部数据库脚本针对“所有内容远端保存”，不适合这次只保存账号和卡密的方案。旧的原子注册迁移也依赖已存在的卡密表，不能独立当作新项目完整初始化脚本。收到新项目配置后，应准备匹配新方案的最小初始化与部署步骤，再验证。

## 本机保存的限制

- 换手机、清理浏览器、卸载后清除网站数据都可能丢失本机内容，账号登录不会自动恢复它们。
- 同一手机换网站地址，本机内容也不会自动跟着移动，先导出再导入。
- 新项目只保存账号和卡密，不能用它恢复尚未备份的角色和聊天。
- 多人真实共享的内容需要远端服务；纯本机保存不等于具备跨设备同步或公共主题、共享动态等能力。
- 免费服务仍有配额及暂停风险，不承诺永久免费或永不暂停；当前旧服务是否可恢复需另行核实。
